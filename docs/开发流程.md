# 开发流程

本项目采用 **源码分层（`src/`）+ Shopify 产物（`theme/`）**：日常改 `src/`，CLI 只认 `theme/`。

**设计稿：** [Stitch 项目 Atelier Maison / Quiet Atelier](https://stitch.withgoogle.com/projects/1774047669727653192)  
对照文件：`stitch/DESIGN.md`、`stitch/desktop-*.html` · 详见 [主题作品-简约轻奢DTC.md](./主题作品-简约轻奢DTC.md)

---

## 一键开发

```bash
npm install   # 第一次
npm run dev   # 或双击 start.bat
```

`npm run dev` 会同时跑 3 件事：

| 进程 | 干什么 |
|------|--------|
| **liquid 监听** | `src/sections`、`src/snippets` 一改 → 扁平拷到 `theme/` |
| **Vite** | 管 `src/entrypoints` 的 JS/CSS，支持 HMR |
| **Shopify CLI** | 对着 `theme/` 做本地预览（店铺 `cyan-dev-store1`） |

终端里会出现预览地址（一般是 `http://127.0.0.1:9292`），用那个看效果。

---

## 常用命令（`package.json` scripts）

| 命令 | 用途 |
|------|------|
| `npm run dev` | 本地开发（最常用） |
| `npm run build` | 构建：Liquid 扁平化 + Vite 生产打包 |
| `npm run push` | 先 build，再推到店铺 |
| `npm run pull` | 从店铺拉回 `theme/` |

下面这些一般不用手敲，由上面的命令调用：

| 命令 | 用途 |
|------|------|
| `npm run build:liquid` | 只跑 Liquid 同步 |
| `npm run build:vite` | 只跑 Vite 打包 |
| `npm run watch:liquid` | 只监听 Liquid |
| `npm run dev:vite` | 只开 Vite |
| `npm run dev:shopify` | 只开 Shopify theme dev |

## 按改什么决定改哪里

| 要改的东西 | 改哪里 | 怎么看到 |
|------------|--------|----------|
| 新建/定制 Section、Snippet | `src/sections/...` 或 `src/snippets/...` | liquid 监听自动同步到 `theme/` |
| 全局自定义 JS/CSS | `src/entrypoints/theme.js` / `theme.css` | Vite HMR，经 `vite-tag` 加载 |
| Dawn 原版且暂不接管 | 直接改 `theme/sections/...` 等 | CLI 热更新；但没进 `src` 体系 |
| 主题颜色/字体等后台项 | 浏览器主题编辑器 | 写入 `theme/config/settings_data.json` |

**推荐习惯：** 新功能、要长期维护的 → 写 `src/`；没动过的 Dawn 文件 → 留在 `theme/`。

## 完整例子：改 hero-banner

1. 编辑 `src/sections/marketing/hero-banner/hero-banner.liquid`（或 `.css`）
2. `npm run dev` 已开着 → 自动同步到 `theme/sections/` + `theme/assets/section-*.css`
3. 浏览器预览刷新看效果
4. 若还没挂到首页：主题编辑器 → 添加区块 →「Hero 首屏Banner」

### 改全局样式

1. 编辑 `src/entrypoints/theme.css`
2. Vite 热更新（`theme/layout/theme.liquid` 里已有 `{% render 'vite-tag', entry: 'theme.js' %}`）

## 上线 / 同步店铺

```bash
npm run build   # liquid 扁平化 + Vite 生产打包
npm run push    # 先 build，再推到店铺（未发布主题）

npm run pull    # 从店铺拉回 theme/（可能覆盖产物，自定义以 src 为准）
```

注意：

- `pull` 拉的是扁平主题，**不会**自动还原成 `src/` 分层
- 自定义逻辑以 `src` 为准；不要手改由构建生成的 `theme` 文件（如 `vite-tag.liquid`、`section-*.css` 等）

## 心智模型

```
        你写代码
           │
     ┌─────┴─────┐
     ▼           ▼
   src/        theme/ 里 Dawn 原文件
     │           │
     │ build/watch
     ▼           │
  theme/ 扁平产物 ◄┘
     │
     ▼
  Shopify CLI 预览 / push
```

**一句话：** `npm run dev` 开着 → 定制改 `src/`，原版小改可动 `theme/` → 浏览器看预览 → 满意再 `npm run push`。

## `vite.config.js` 配置说明

文件位置：项目根目录 `vite.config.js`。

### 主要作用

告诉 Vite **怎么和本仓库的 Shopify 主题工程对接**。没有这份配置，Vite 不知道：

- 主题在哪个目录（`theme/`）
- 源码 / 入口在哪（`src/`、`src/entrypoints`）
- 怎么在 Liquid 里加载打包结果（生成 `vite-tag.liquid`）

`shopify({...})` 来自 `vite-plugin-shopify`；下面每一项都是在填这些约定。  
**注意：** Liquid 分层同步是 `scripts/build-liquid.mjs` 的事，**不归** `vite.config.js` 管。

### 当前配置（对照源码）

```js
import { defineConfig } from 'vite';
import shopify from 'vite-plugin-shopify';

export default defineConfig({
  plugins: [
    shopify({
      themeRoot: 'theme',
      sourceCodeDir: 'src',
      entrypointsDir: 'src/entrypoints',
      snippetFile: 'vite-tag.liquid',
      versionNumbers: false,
      themeHotReload: true,
    }),
  ],
  build: {
    // 保留 Dawn 原有 assets，避免清空 theme/assets
    emptyOutDir: false,
  },
});
```

### 逐项含义

| 配置 | 作用 |
|------|------|
| `themeRoot: 'theme'` | Shopify 主题根目录是 `theme/`（CLI 的 `--path theme` 也指这里） |
| `sourceCodeDir: 'src'` | 前端源码根是 `src/`；`@/`、`~/` 别名也指向这里 |
| `entrypointsDir: 'src/entrypoints'` | 把该目录下的 `theme.js` / `theme.css` 当成打包入口 |
| `snippetFile: 'vite-tag.liquid'` | 自动生成/更新 `theme/snippets/vite-tag.liquid`，给 layout 用 `render` 引入 |
| `versionNumbers: false` | 生产环境 URL 不追加 Shopify `?v=`，主要靠 Vite 的哈希文件名 |
| `themeHotReload: true` | 开发时配合主题热更新（改资源能更快反映到预览） |
| `build.emptyOutDir: false` | **不要清空** `theme/assets/`，否则 Dawn 自带的 `base.css`、`global.js` 等会被删掉 |

### 和日常开发的关系

```
src/entrypoints/theme.js
        │
   Vite（读 vite.config.js）
        │
        ├─ 开发（npm run dev）：本机服务 + HMR → vite-tag 指到 Vite
        └─ 构建（npm run build）：写出 theme/assets/theme-xxxxx.js|.css
                                  并更新 snippets/vite-tag.liquid
```

layout 里对应一行：

```liquid
{% render 'vite-tag', entry: 'theme.js' %}
```

**一句话：** 这份配置把「Vite 前端工程」接到「`theme/` 这套 Shopify 目录」上。

## `src/entrypoints/` 入口说明

目录里的 `.js` / `.css`（以及 ts/scss 等）都会被 Vite 当成**打包入口**。可以多个；入门用一个 `theme.js` 即可。

### 当前文件

| 文件 | 作用 |
|------|------|
| `theme.js` | 全站 JS 主入口（内含 `import './theme.css'`） |
| `theme.css` | 全站样式；也可被单独当作入口 |

layout 里已引入：

```liquid
{% render 'vite-tag', entry: 'theme.js' %}
```

### 多个入口：什么场景？

需要**按页面拆包**、避免全站打一个大包时，例如：

```
src/entrypoints/
  theme.js       ← 全站公共
  product.js     ← 仅商品页
  collection.js  ← 仅集合页
```

### 多个入口：怎么写？

1. 在 `src/entrypoints/` 新建对应文件（如 `product.js`）
2. 在需要的地方用 `vite-tag` 引入（模板、section 或 layout 均可）：

```liquid
{% render 'vite-tag', entry: 'theme.js' %}
{% render 'vite-tag', entry: 'product.js' %}
```

`entry` 填**文件名**（与入口文件名一致）。改完后开发环境 Vite 会识别新入口；推送前执行 `npm run build` 更新产物和 `vite-tag.liquid`。

### 打包后文件去哪？`render` 和 `assets` 别混

```
src/entrypoints/theme.js  /  product.js  /  ...
        │  npm run build（Vite）
        ▼
theme/assets/theme-xxxxx.js、product-xxxxx.js（带哈希）
        │
同时更新 theme/snippets/vite-tag.liquid（入口名 → 哈希文件名的对照）
```

页面上写的仍是：

```liquid
{% render 'vite-tag', entry: 'product.js' %}
```

注意两步，避免误解：

1. **`{% render 'vite-tag' %}`** → 和 `render 'meta-tags'` 一样，只引入 **`theme/snippets/vite-tag.liquid`**，**不会**直接读 `assets/`  
2. **snippet 内部**再输出 `<script src=".../assets/product-xxxxx.js">`，浏览器才去加载 **`theme/assets/`** 里的打包文件  

| | 含义 |
|--|------|
| `render 'xxx'` | 永远找 `snippets/xxx.liquid` |
| `entry: 'product.js'` | 传给 snippet 的参数（告诉它挂哪个入口） |
| `theme/assets/product-xxxxx.js` | Vite 产物；由 snippet 生成的标签加载 |

开发时（`npm run dev`）多半走 Vite 开发服务器（HMR）；**build 之后**才稳定落在 `theme/assets/`，再随 `theme push` 上店铺。

### 一般什么情况会改这里？

| 会改 | 说明 |
|------|------|
| 全站通用 JS/CSS | 直接改 `theme.js` / `theme.css`，或从这里 `import` 其他模块 |
| 按页面拆包 | 新增 `product.js` 等，并在对应页 `render 'vite-tag'` |
| 组件 JS 仍跟全站一起加载 | 在 `theme.js` 里写 `import '@/sections/.../xxx.js'`，**不必**新建入口 |

| 通常不改这里 | 改哪里 |
|--------------|--------|
| 某个 Banner 的 Liquid / 专用 CSS | `src/sections/...` |
| Dawn 原版区块 | `theme/sections/...` |

**简记：** 不是每个 section 都要新建入口；多数区块走 Liquid + CSS。只有「全站前端」或「要单独拆包的页面脚本」才动 `entrypoints/`。
